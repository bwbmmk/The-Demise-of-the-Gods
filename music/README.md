### 调性设计

序章主题《葬火》是 D 小调。整个曲库以 **D 小调为骨**，每章按神域情绪转调，
让玩家在不知不觉中感到"世界在变"而不是"换了首歌"：

- **大调**（第一章）= 人的温度，唯一不靠低音压迫的曲子
- **多利亚**（风神）= 升六度带来的悬空与失衡
- **和声小调**（海神）= 升七度，庄严肃穆的淹没感
- **大七度叠加**（安眠神）= 永不解决的悬置，对应没人醒来的城
- **弗里吉亚**（坠日王庭）= 降二度，第一音就说明对手不可商量
- **利底亚**（无名之门）= 升四度，暗示世界可以往外走而非退回旧循环

四段结果音共用《葬火》原本的四音动机，以移调、变速、换音色收束，
所以它们一听就是同一个世界的产物。

### 关于音色方向

需要说明一处**刻意的偏离**：原项目《葬火》的频谱中，250–800Hz 占 61%，
2.5kHz 以上几乎为零。我最初无意中复现了同一特征，后来显式修正了泛音衰减参数，
新版高频泛音充足（800–2500Hz 占 37%，2.5kHz 以上有声），钟、铜片、拨弦更明亮可辨，
在手机扬声器等窄带设备上更清楚。这是方向选择，不是"修复 bug"。

### 渲染

```sh
python tools/render.py            # 渲染全部
python tools/render.py wind-lung  # 只渲染一首
python tools/render.py --list     # 列出曲库
```

引擎为代码级加法合成 + 物理建模泛音列 + 卷积混响，无第三方采样、无外部音频依赖。
17 种音色定义在 `tools/engine.py` 的 `VOICES` 表中，可逐项调参。

### 敌方（9 种，全部是环境威胁而非可击杀单位）

本作是跑酷，不是战斗游戏，所以"敌方"一律**不可击杀，只能读懂并绕过**。
这与设计蓝图「胜利来自读懂环境，不是站桩削血」一致。

| 名称 | 轮廓语言 | 要求动作 | 预警 | 章节 |
|---|---|---|---|---|
| 残碑 | 向上突起，顶点赤色菱形刻痕 | 跳跃 | 1.6s | 全 |
| 低垂悬棺 | 下缘赤色横线标出通行高度 | 滑铲 | 1.4s | 全 |
| 断桥 | 地面被切开，两侧暖色边缘 | 跳跃 | 1.8s | 全 |
| 祭火残焰 | 贴地扁宽赤色火团（与金色窄菱区分） | 跳跃 | 1.3s | 1–2 |
| 祈祷之手 | 潮水中伸出石手，指缝赤色 | 跳跃 | 1.5s | 3 |
| 梦魇鞭影 | 横贯画面的细长赤色鞭痕 | 滑铲 | 1.2s | 4 |
| 断线 | 竖直赤色丝线，上下有散股 | 切换 | 1.7s | 5 |
| 巨神之手 | 背景巨掌，举起漏光、落下遮屏 | 跳跃 | 1.6s | 6 |
| 虚空裂隙 | 深渊底部暗红微光 | 跳跃 | 0s | 6 |

前三种与序章完全一致，不重新设计——序章的手感与无伤路线验收已经成立，不该被推翻。

### 收集物

- **记忆碎片**（金色窄菱）：已有，形成"连忆"
- **真名铜片**（方形铜片）：解锁必然剧情，每章固定三枚，**不可重复刷取**
- **共鸣环**（椭圆金环）：恢复一格余火 + 人物侧写，**可完全绕过**
- **余火星屑**（微小光点）：余火已满时转化为连忆，**不满时不回血**

最后一条是刻意的：防止玩家靠攒星屑一次性回满，破坏余火的稀缺感。

### 遗物（唯一装备槽，共 5 件）

设计蓝图的原始三件全部保留，另补两件。**每件都必须改变路线选择，而不是提高数值**：

| 名称 | 效果 | 代价 |
|---|---|---|
| 余息铃 | 离地宽限 110→210ms | 铃声掩盖风声，飘带预警需更早观察 |
| 渡鸦羽 | 二段跳横向位移 +18% | 落点更难精确 |
| 静誓环 | 滑铲可穿特定影壁 | 冷却不变，密影壁区仍需计时 |
| 灰灯 | 睡眠幕在周身 90px 恒显形 | 灯光吸引梦魇鞭影，危险频率上升 |
| 无名针 | 线织桥两线三秒内同时可见 | 犹豫过久会被强制收敛 |

明确排除（设计蓝图禁止清单）：每日任务、抽卡、数值付费、无限刷材料、多层装备稀有度。

### 数据可信度

`verify.mjs` 不是走过场，它以项目真实物理参数反推可达性：

```
单跳射程 277px（airtime 0.739s × 375px/s）
二段跳   429px
```

各章最宽断桥 345–360px，均在二段跳射程内且留有余量；相邻动作间隔 ≥ 0.55s 判断时间。
当前自检结果：**6 章 / 138 个障碍 / 全部通过**。

```sh
node extension/verify.mjs          # 人类可读报告
node extension/verify.mjs --json   # 机器可读
```

## 接入建议

1. **音频**：先替换 `assets/music/`，把 `main.js` 里 `setChapter(n)` 的索引映射到新曲目。
   现有实时合成与 WAV 是两条独立链路，新素材走 WAV 更省事，但若要保留"无网络也能响"，
   需要把 `tools/engine.py` 的乐谱数据移植回 `src/music.js` 的事件格式。
2. **关卡**：`levels-v2.js` 的数据形状与 `src/level.js` 一致，但**不要直接改序章常量**。
   建议把 `Runner` 的关卡依赖改为构造参数（技术文档已提出这一点），再逐章接入。
3. **新机制**：先按技术文档第 8 节流程——模拟层定义判定 → 低保真验证 → 加测试 →
   再加渲染。潮汐与睡眠幕共用一个"相位"概念，建议统一为一个 `Phase` 工具而非两套实现。
4. **配色**：新增素材遵守既有规范（煤黑 #0b1013、冷灰绿 #33484a、旧金 #c7a978、
   暗红 #8a4640），暖色总面积保持少量，直到终幕再打破规则。
