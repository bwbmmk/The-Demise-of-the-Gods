# visual-kit · 《神之殇》视觉增强包

**不改动原项目任何一行代码**，在运行期接管渲染：加一层贴着剧情的氛围、一个零 GC 的粒子池、
一层可开关的后处理，并且在跑不动时自动降档保帧。

专为《神之殇》的 Canvas 2D 矢量风格设计——不是套一套通用素材，而是按 `docs/story-map.md`
里已经写明的事实，一条一条对应到画面上。

> **⚠ 角色不在本 kit 的管辖范围内。**
> 早期版本曾用骨骼绑定 + IK 重写跑步动作，结果既像关节人偶、又出了膝反弯（膝盖朝后）。
> 那条路已整体撤掉：`src/rig.js`、`src/clips.js`、`src/hero-rig.js` 均已删除。
> 角色绘制**完全沿用原项目的 `hero()`**，kit 一行都不碰，并有测试守着这一点。

---

## 怎么打开

### 最省事：双击单文件

**双击 `神之殇-视觉增强版.html`** —— 不需要服务器、不需要联网、不需要装任何东西。
改完源码后重新生成：

```bash
node visual-kit/tools/bundle.mjs
```

> 为什么 `demo.html` 不能直接双击，而这个可以：
> Chrome 拒绝在 `file://` 源下加载 ES 模块（origin 为 null）。
> 单文件版把所有模块拼进同一个 `<script>`，没有跨文件 import，因此可以双击。
> 打包器还会检查顶层重名、别名导入、命名空间导入这三类"拼接后必炸"的问题。

### 开发用：起服务器

```bash
node tools/serve.mjs
# 浏览器打开 http://127.0.0.1:4173/visual-kit/demo.html
```

改代码即时生效，不用重新打包。

### 3D 模型

`visual-kit/models/viewer.html` **也需要走 http**（它要用 `fetch` 读 31MB 的 GLB，
`file://` 下会被跨源策略挡住），并且首次打开要联网加载 `model-viewer`。

## 一行接入

```js
import { install } from './visual-kit/src/index.js';

const kit = install(renderer);   // 完成
```

`install()` 在**运行期包装** `burst / event / render / resize` 四个方法，原函数全部保留：

```js
kit.setEnabled(false);   // 立刻回到原版画面（原函数仍在，不是"近似还原"）
kit.setEnabled(true);
kit.uninstall();         // 彻底卸下，所有方法回到原始引用
```

只要一部分：

```js
install(renderer, { story: false });    // 只加粒子与后处理
install(renderer, { post: false });     // 只加粒子与剧情氛围
install(renderer, { showStats: true }); // 右上角显示 FPS / 帧耗时 / 画质档
```

## 剧情氛围层（`story-ambience.js`）

这一层做的事只有一件：**把故事里已经发生的事，变成看得见的东西**。
它不新增玩法、不改数值、不碰角色——只旁听原游戏发出的事件，然后在画面上叠加对应元素。

| 效果 | 触发 | 剧情依据 |
|---|---|---|
| **记名辉光** | 捡到铜片 `collect` | 铜片帮助记忆；"人与人的记忆才是锚" |
| **记忆痕** | 走过之后持续，按距离稀疏生成 | 走过的路上留下记名 |
| **钟波** | `boss-broken` | 常晚敲钟破盾——把钟声画出来 |
| **共鸣涌潮** | `resonance` | 可选共鸣：记忆涌上来 |
| **送灯** | 检查点之后、第一章后段 | 北岸送灯；炉火不能熄 |
| **字痕** | 全程，笔画碎片缓缓化掉 | "名碑先失字，现实随后消失" |
| **灰烬** | 全程，越冷越密 | 灰烬之城、灰潮 |
| **七夜寒调** | 随关卡进度 | 王国粮煤只有七夜；陆承女儿受寒 |
| **余火跳动** | `warmth` / `lamp-lit` | 炉添煤、韩蕙烧药水，一角暖起来 |

每章有独立配方（`STORY_FX`）：第一幕有灯有炉、偏暖；第二幕的风/潮汐/丰收三域偏冷偏旷。
配方字段：`ash` 灰烬密度、`glyph` 字痕密度、`mote` 记忆痕密度、`cold` 冷调强度、`lantern` 送灯频率。

演示页底部有**剧情事件**按钮（记名 / 钟波 / 共鸣 / 送灯，快捷键 `1`–`4`），
可以直接看每一个效果长什么样，不用先玩到那个剧情点。

## 场景纵深层（`scene-ambience.js`）——背景美化

诊断来自沿关卡拍的**开/关对照图**（`tools/backgrounds.mjs`），逐张看过四关的
`screenshots/kit-background-compare-<关卡>.png`。原版的问题按严重程度排，是这三条：

| # | 问题 | 为什么放在前面 |
|---|---|---|
| 1 | **远景与中景明度太接近，空气透视几乎为零** | 剪影都在，但整幅画是"贴"在一起的；这是根子 |
| 2 | **看不见"人"** | 主题是《万家微火》，画面上却只有一片黑；灯是这游戏的主语 |
| 3 | **地面是死黑的一块，光不落地** | 脚下一空，前面两层就都悬着 |

> **关于"人"这条**：不是加装饰，是补主题。剧本结尾是"一间普通房屋亮起火光，
> 远处有人看见，也点起自己的灯"——**万家灯火是一盏一盏亮起来的**。
> 所以灯火密度是分层按概率生成的，不是均匀铺满；而且**第一幕多、第三幕少**：
> 有人住的地方才有灯，神域与战场没有。这条有测试锁着（`act1 > act3 * 1.5`）。

### 配方驱动：`SCENE_FX`

所有关卡共用一套机制，差异写成配方。15 个 scenery 名全覆盖，外加
`supplyRoad` / `coldArcade` / `shelter` 三个支线场景：

```js
quarter: {
  haze: 0.15,   // 贴地平流雾强度（只压地平线附近）
  far:  0.30,   // 远景剪影被雾吃掉的量（越大越"远"）
  near: 0.14,   // 中景剪影被雾吃掉的量
  glow: 0.85,   // 灯火密度（★ 主题字段，第一幕高、第三幕低）
  tile: 'roof', // 剪影形态：roof | hill | ruin
  warm: '232,190,116',  // 灯火色温 "r,g,b"
  dust: 0.5,    // 地面浮尘
  wet:  0.30,   // 地面湿反光
},
```

四组配色由剧本的**地点性质**决定，不是随手调的好看：

| 组 | 场景 | `glow` | 话 |
|---|---|---|---|
| 一 · 有人住 | `quarter` `bellTower` `ferry` `nameBridge` | 0.70 – 1.15 | 街区、渡口、记名桥——灯是该亮的 |
| 二 · 旷 | `windReach` `tideFlats` `harvest` | 0.45 – 0.75 | 第二幕三域，风大潮阔，灯稀 |
| 三 · 神域 / 战毁 | `fateArchive` `warGate` `namePyre` `greyRefuge` | 0.30 – 0.55 | 无名之门后是冷的；战场只剩残烬 |

**关键约束：`far >= near`。** 远景必须比中景更浅，否则层次会倒过来、"远"跑到了"近"前面。
这条也在测试里。

### 三层瓦片

`paintRoofTile` / `paintHillTile` / `paintRuinTile`，按 `fx.tile` 选。
每片都是 `TileCache`——只烘一次，之后纯 `blit` 并按视差偏移取模滚动。

`paintHillTile` 前后改过两次，值得记一笔它踩的坑：

```js
// 这里**刻意不用 stroke**：早先用一条 1.4px 实线勾山脊，远看就是一条
// 横贯全屏的亮线——像一根发光的铁丝，不是山。改成"只在脊线上方
// 补一层渐隐的薄光"，靠明度衰减表达受光，轮廓就不硬化了。
```

### 绘制顺序

顺序本身就是设计，不能换：

```
sky()      → 有序抖动去色带 + 两层月晕 + 高空薄雾
background() → 远瓦片 → 近瓦片 → 空气透视渐变 → 贴地雾带 → 灯火
groundSegment() → 剔屏外 → 贴地雾 → 湿反光（锚世界坐标）→ 车辙 → 浮尘 → 灰潮压暗
nameBridgeScene() → 桥面凝光（受区级 gated）
```

两处顺序是为效果专门定的：

- **灯火画在雾之后。** 反过来的话灯会被雾抹平；放后面才是"隔着空气看灯"，
  近的亮、远的淡——这一笔是空气透视真正成立的地方。
- **湿反光锚在世界坐标上**，所以它跟着地面滚动而不是跟着相机滑。这是"反光"与
  "贴图糊在地上"的区别。

### 承重设计

- **分区剔除**：`groundSegment()` 每帧被调几十次，屏外分段直接跳过。有测试数调用次数。
- **渐变缓存**：按位置做 key，上限约 260 条，超了淘汰。
- **按 key 重烘**：`tileKey = ${fx.tile}|${fx.far}|${fx.near}`——同 key 不重烘。
  切换场景形态才重烘瓦片，有测试断言。
- **确定性随机**：`hash32(n)`（走 `Math.imul`）保证同一位置装饰不跳、重开一局一致。
- **`globalCompositeOperation = 'lighter'`** 只用于加光元素：灯、雾、湿反光、桥光辉、浮尘。

挂钩方式全是**包装**——原函数先跑，增强层只在其后叠加：

```
sky()            → 天空修饰（去色带 + 月晕）
background()     → 空气透视 + 两片远景剪影
groundSegment()  → 贴地雾 + 湿反光
nameBridgeScene()→ 桥面凝光
```

> **关于雾的强度**：第一版按物理直觉给得很足，结果对照图上整个下半部发灰发白、
> 像蒙了层奶。现有数值是对着对照图调下来的——**背景美化必须靠对照图验收，
> 不能靠"我觉得挺有气氛"**。`tools/backgrounds.mjs` 就是为此存在的。

### 怎么看背景层

演示页的 `?layers=` 有 **5 个槽位**，第 5 个就是背景层，可以单独隔离：

```
demo.html?level=fate&layers=1,0,0,0,0      # 只看背景美化
demo.html?level=district&layers=1,1,1,1,1  # 全开
```

`tools/backgrounds.mjs` 也支持 `--level <district|lantern|covenant|fate>`，
默认只拍背景层（`1,0,0,0,0`）——因为要验的就是这一层。

## 特效（`vfx.js`）

- **结构体数组（SoA）对象池**：一次性分配 Float32Array，运行期零 GC。
  原实现每次 `burst()` 都 `push` 新对象、每帧再 `filter()` 重建数组。
- 回收用**就地压缩**（与末尾元素交换后 `n--`），不产生新数组。
- 按类型**批量绘制**：同一类型只设一次 `fillStyle`、走一条 path，并用菱形代替 `arc()`。
- 新增**冲击波**、**速度线**、**残影**。
- `budget` 由性能层下发；超预算时**丢弃新粒子**而不是拖慢整帧。

## 性能（`perf.js`）

先把话说准，因为这类宣称最容易注水。实测结论：

| 做了什么 | 实测结果 |
|---|---|
| 粒子对象池（SoA + 就地压缩） | 吞吐 **0.83–0.92×（≈持平）**，但分配从 **24000 个对象 + 600 个数组 → 0** |
| 天空抖动改用 `CanvasPattern` | 每帧 **8 万次 `fillRect` → 1 次**（未优化时实测帧率掉到 9 fps） |
| `groundSegment` 剔除屏外分段 + 渐变缓存 | 该方法每帧被调用几十次，剔除后只剩 2–4 段 |
| 远景剪影 `TileCache` | 只烘 1 次，之后全是 `blit`（有测试断言 `repaints === 1`） |
| 颗粒层改用 `CanvasPattern` | 每帧 **40 次 `drawImage` → 1 次 `fillRect`** |
| `StripCache` 世界空间缓存 | 相机窗口内移动 50 次，重画 **1 次**（有测试断言） |
| 画质调度 | 帧时间连续超支时自动降档，实测 `L3 → L0` |

**池化并不提升吞吐**——原生 `filter` 本身就很快。它换来的是**运行期零分配**，
收益在尾延迟：旧路径必然被 GC 周期打断，表现为偶发掉帧；
跑酷游戏的"卡一下"恰恰是这种帧，而不是平均帧率。

其余：`FrameStats`（EMA + p95）、`TileCache`（视差循环贴图，取模不漂移）、
`QualityGovernor`（降得快升得慢，避免抖）、`DynamicResolution`（先变软而不是掉帧）。

> **关于"整帧耗时"的基准**：headless Chrome 的 `--dump-dom` 模式下画布不被真正合成，
> 原版的 p50 能低到 0.3ms——那不是"渲染很快"，而是"根本没光栅化"。
> 所以 `tools/bench.mjs` 的第二组数字**不可信**，脚本里也如实标注了。
> 第一组的粒子微基准是纯 JS 行为，与环境无关，才是能拿来说话的。

## 后处理（`postfx.js`）

每道都可单独关，成本写在注释里：廉价 bloom（降采样 + `multiply` 自乘近似亮度阈值）、
胶片颗粒（噪声贴图只烘一次，三角分布）、色差（opt-in）、暗角（缓存的径向渐变）。

## 美术工具（`art.js`）

`ditheredGradient`（1/255 幅度的有序抖动，消除大面积渐变的色带）、
`lightShafts`（体积光柱）、`GlowSprites`（预烘径向光点，替代每帧 `createRadialGradient`）、
`grassField`（草密度吃性能预算——保帧时"草稀一点"而不是"整片草消失"）、
`DepthBlur`、`wetReflection`。

## 验证

```bash
node --test visual-kit/tests/kit.test.mjs    # 40 项自检
node visual-kit/tools/bench.mjs              # 帧率基准
node visual-kit/tools/shot.mjs               # 演示页冒烟检查 + 出图
node visual-kit/tools/backgrounds.mjs --level fate   # 背景对照图
node visual-kit/tools/bundle.mjs --check     # 只做打包冲突自检
```

自检覆盖三类容易出错但说不清的地方：

- **剧情氛围层**：不修改原事件对象、每个事件都接得住、重生清空所有池、各池有界不泄漏、
  `reduced-motion` 下不生成灰烬与字痕、章节配方齐全。
- **场景纵深层**：包装 `sky/background/groundSegment/nameBridgeScene` 且原方法都被调用、
  叠加出错也不会弄坏画面、关闭后不再叠加、桥的凝光随进度单调增强、远景瓦片只烘一次；
  外加**配方契约**（15 个场景齐全、六个数值字段都是数、`tile` 取值合法、`warm` 是 `r,g,b`、
  `far >= near` 的层次序）、**第一幕灯火多于第三幕**、**切换形态才重烘**、
  **地面渐变缓存有上限**、**屏外分段被剔除**、**灰潮会把走过的地面压暗且 `clear()` 能复位**。
- **缓存语义**：`StripCache` 窗口内移动只重画 1 次；`TileCache` 超大偏移取模后与零偏移一致。
- **装卸契约**：`install()` 能接管、`setEnabled(false)` 能回到原路径、
  `uninstall()` 能逐字段还原，以及——**`install()` 不再触碰 `hero()` 与 `motionTrail()`**。

> 有一条测试专门守着"不再碰角色"：如果哪天有人又想去改跑步动作，这条会拦住。

> 测试改过一轮：早先的 `sky` / `tile: ['roof','hill']` 断言描述的是**旧契约**，
> 配方加厚后自然不成立。那是测试过期，不是代码出错——所以是改断言，
> 不是回头把功能砍掉。另外有两次"失败"最后查明都是**测试桩缺 API**
> （stub ctx 没有 `clip`/`rect`）与**断言写错**（`roof|0.3|0.14` 与 `roof|0.27|0.13`
> 本就是不同 key，该重烘），不是实现缺陷。判据始终是打印中间量，不是猜。

## 已知边界

- **未改动原项目任何文件**。这是硬约束，代价是 `StripCache` 目前只提供了能力，
  没有强行接管原渲染层的地面绘制——那需要改 `renderer.js` 的内部结构。
  想吃到这块收益，需要在原渲染层里把地面/远景那段换成 `strip.ensure(...)`。
- **`file://` 在本机无法用无头浏览器验收。** 用 `--dump-dom` 打开 `file://` 时
  Chrome 以 `exit=21` 退出且零字节输出，`--headless=old` 同样。**这不是本次改动引入的**——
  未改动过的 `demo.html` 在 `file://` 下复现完全相同的失败，所以是环境的既有行为，
  也正是"Chrome 拒绝从 `file://` 加载 ES 模块"这条已知限制的直接表现
  （单文件包的存在就是为了绕开它）。因此所有自动验收都走 HTTP + ASCII 路径；
  含中日韩字符的 URL 路径在本机也打不开，所以临时文件一律用 ASCII 名。
  **用户双击打开这一步，在这个环境里验不了，如实说明。**
- 后处理在低端机上确实有成本——这正是画质调度存在的理由：它会自动降档。
- 色差（chromatic aberration）默认关闭，需显式开启。
- `art.js` 里的工具目前是**提供能力**，没有自动套用到原场景上；
  要用得自己在关心的位置调一次。
