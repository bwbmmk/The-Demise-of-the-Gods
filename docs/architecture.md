# 技术架构与扩展说明

> 0.10.1 · 2026-10-05。可玩序章、第一幕、第二幕、第三幕；北岸是独立图文幕间，第二幕使用刹步、周期潮汐、接触坍塌木桥与巨像诱锤。新增 98 页剧情纯享和密码保护的创作者文本编辑通道，以及独立于幕次的两场 Boss 合集。分镜与手记跟随烬当下的知识，沿用人物动机与新版剧本；六锁第一幕 1/6、第二幕 4/6、第三幕 5/6。创作和后续任务以 [总蓝图（含剧透）](design-bible.md)、[故事表（含剧透）](story-map.md)、[任务表（含剧透）](roadmap.md) 为准。

## 当前技术选择

原生 JavaScript ES Modules + Canvas 2D + Web Audio。没有框架、构建依赖、联网字体或外部图片。Node 仅用于开发服务器、打包和测试；生成的单文件 Demo 运行时不需要 Node。

这个技术底座适合当前小型原型。若后续确定大规模骨骼动画、复杂编辑器或主机发布，应在垂直切片验证后评估迁移到成熟 2D 引擎；现在不提前引入复杂工程。

## 时间与空间

模拟固定为 120 Hz，`requestAnimationFrame` 负责累积时间并执行模拟。单帧间隔上限为 80ms，避免长时间卡顿后穿越障碍；代价是设备严重卡顿时模拟会慢于现实。离开标签页或失焦自动暂停。

逻辑高度 810，地面 y=606。宽度由实际容器宽高比计算；输出像素密度最多使用 2 倍。世界 x 向右递增、y 向下递增；玩家 x 是脚下中心点。摄像机保持角色位于靠左位置。地形、角色与 UI 使用同一套世界投影，页面 HUD 保持 CSS 尺寸。

宽屏提供更多预判距离。窄竖屏有横屏建议；当前未为竖屏重新设计关卡难度，不宣称手机竖屏与桌面具有等同体验。

## 状态机

```text
menu → intro（四幅漫画）→ arrival → running
running → defeat → dead → running（从检查点恢复）
running → departure → intro（本章幕末）→ won
prologue won → district intro（第一幕开场）→ battle-entry → arrival → running
district boss-defeated → intro（第一幕幕末）→ won → intermission intro（五幅图文）→ won → covenant intro（第二幕开场）→ battle-entry → arrival → running
covenant won → fate intro（第三幕两幅开场）→ battle-entry → arrival → running
menu → intro（theater：五段目录与片段跳转）→ 下一段阅读 / menu
menu → Boss 合集 dialog → battle-entry → running（第一轮练习）→ won → battle-entry（重战）
running → encounter（安全处对白）→ running
won → arrival（次要重玩按钮）
running / encounter / arrival / defeat / departure → paused → 原状态
返回菜单 → 取消演出
重开 → 重置模拟、计时与收集；保留已读手记
```

模拟内部只关心 `running / dead / won`；只有外层 running 模式推进它。演出独立消费帧时间，暂停时演出时钟与粒子冻结，Enter 或跳过按钮直接完成当前演出并切换对应状态。打开档案或指南记录 resumeMode，关闭回到原游戏/演出状态；原本已经暂停则不自动恢复。

`jump / slide / land / collect / hit / checkpoint / respawn / launch / resonance / dead / won` 是模拟发出的表现事件，事件队列逐帧消费。resonance 携带 ring ID 解锁人物记忆，dead 携带 falling 区分跪倒与坠落。输入产生的跳跃事件即时处理，避免等到下一帧才出现反馈。

## 碰撞与容错

使用收紧的 AABB，披风、短剑和视觉光晕不参与碰撞。残碑与悬棺各有独立碰撞边界；滑铲改变玩家高度。普通障碍造成一次伤害，1.7 秒保护避免连续扣血。保护期可以穿过实体，是原型的明确设计选择。

断桥用玩家脚点是否位于缺口判断，不允许从桥下吸附回地面。掉落超过 y=900 扣血并恢复检查点；不受普通受击保护影响，避免无限坠落。空中快速下落后在短窗口内落地会自动滑铲。

二段跳消耗剩余空中跳次数；着地刷新。离地后有 110ms 宽限，宽限过期则只保留一次空中跳。140ms 输入缓冲主要覆盖用完空中跳后的提前落地输入，不额外生成第三次跳跃。

## 检查点与收集一致性

进入新章节时保存已收集碎片集合并恢复一格生命。掉落或死亡重试会恢复该集合，检查点之后的收集回滚，不能靠反复重试刷数量。掉落扣血；死亡界面主动重试补满三格。总游玩时间继续累计，重燃次数累计。

关卡进度保存于 `requiem.progress.v1`：只在检查点保存该点已取得的碎片、共鸣、铜片、旗标及计时/重燃数，恢复不增加重燃。按关卡独立存储；未知检查点、坏数据、错误集合与未来版本回退到重新开始。尚未保存音量/静音设置。手记单独保存在 localStorage 的 `requiem.journal.v2`，结构为 `{version:2,ids:[...]}`；迁移 v1 序章 p/r，旧第一幕条目不迁移，旧键保留；仅加载当前白名单 ID，错误格式、未来版本、禁止存储或空间不足均安全回退。手记已读不随物理回档撤销；一次运行内通过 session 去重排队，重玩清空 session 但保留归档。

A-04 已实现检查点部分；后续设置存档增加 `schemaVersion / levelId / checkpointId / collectedIds / settings`，必须迁移旧手记而不是覆盖它。不能把已经看过某条线索当作已经完成本次关卡目标。

## 表现与叙事预算

轨迹按物理步长 120Hz 记录，最多 96 点，显示最近 0.7 秒；渲染插值末端与持火手一致，Catmull–Rom 每段三次细分后生成连续带面。120Hz 是模拟采样率，不承诺设备实际帧率。少量低透明度残影保留速度感，丝带宽度随余火强度变化。关节姿态与碰撞盒分离。

火焰强度为三格 1、两格 0.68、一格 0.36、零格 0；指数平滑消除受击/补火突变。演出使用独立熄灭/点燃包络。三境使用独立背景函数，检查点后 500px 交叠，地面颜色按世界坐标选材质，危险轮廓维持统一。

序章主线按距离解锁，第一幕按自身路线事件解锁并立即归档；跨关不会触发序章距离记录。弹句等待无教学、无章节标题和前方 1.2 秒内无障碍的间隙。文字已显示时不会强制消失，默认 4.6 秒后结束；未来盲玩要检查阅读负担。结尾 p8 在 departure 完成（含跳过）解锁。可选共鸣不会锁住主线说明。游戏内档案仅渲染已解锁正文，未知条目隐藏标题和内容。

## 新内容接入

1. 在 `level.js` 添加一个使用稳定 ID 的关卡数据对象，并写明入口、出口和检查点。
2. 先在模拟层定义该障碍的作用与判定；用低保真图形确认反馈。
3. 添加可完成路线与错误输入的测试，保证至少一条无需受伤的路径。
4. 再在 renderer 中加入专属轮廓、预警和动画。
5. 将字幕挂到安全路段，在 narrative.js 中配置稳定线索 ID；若扩展分支条件，继续扩展独立叙事模块，不把条件堆入主循环。

Runner 已通过构造参数或 loadLevel 注入独立关卡。物品直接发出 item 事件，无需再放同名旗标；必要物品按跨过 x 获取，可选物品仍碰撞收集。旗标按跨过触发点发出，检查点同时回滚物品和旗标，避免漏播/重复获得。地面材料按当前关卡分段取值，断口边缘使用自身高差；第一幕出口不再画序章门槛。仍无关卡编辑器或通用资源系统。

## 性能与可维护性

障碍与碎片只绘制视野附近的对象；粒子上限 220；音效节点结束后断开连接。主循环仍遍历当前小关卡数据，几十个对象足够轻；扩展至上千实体时应增加区间索引和背景层离屏缓存。

程序绘制的景物没有外部美术素材依赖。声音仅在用户开启后启动；不申请麦克风权限。开发服务器只监听 `127.0.0.1`，用于本机预览，不是互联网部署方案。

## 构建

`tools/build.mjs` 按依赖顺序将源码模块内联，移除当前简单的 import/export 声明，再把 CSS 与 JS 注入 HTML。新增五段 WAV 由 selected/manifest.json 索引，以 Base64 内置到 audio-clips.js；开发模块则读取同一份本地 WAV。它专为现有模块布局编写，不是通用打包器。增加跨文件同名顶层变量、动态 import 或第三方依赖时，应迁移到标准打包工具。

0.3.1 音频生命周期：录音走档案/事件总线，合成主题走 scoreBus；档案淡化主题，事件压低背景。异步解码有缓存，失败回退短合成音；generation 令牌防止关闭档案、静音或重启后迟到播放。事件不堆叠、1.5 秒去抖；结算保留尾音，真实暂停静音，重试淡出。新增测试覆盖这些状态及离线内置文件与源 WAV 字节一致性。外部关卡的独立审阅和模拟边界见 music-pack-review.md。

0.3.1 浏览器验证：音频校验页五段全部成功解码，依次显示档案、转场、共鸣、战败和入门的播放状态，事件段互相替换；无控制台错误。正式单文件入口已验证档案内 M 静音和帮助说明。模块音频 URL 相对 audio-clips.js 解析，校验页位于 tests 子目录也能正常加载。实际扬声器听感仍需在用户设备体验。

不要手动编辑 `神之殇-demo.html`；运行 `npm run build` 更新它。

`renderer.resize()` 在画布尺寸未变时不再重设 `canvas.width`。重设会清空整张画布，而暂停/对白/转场切换 `playing` class 会连发 `ResizeObserver` 回调，导致这些时刻闪黑；离屏截图更会直接拍成黑图。这条也解释了为什么截图脚本改为"页面导出画布 + chrome 截图合成"。

守灯人配置在 level.enemies；Runner 独占 enemyStates 与 projectiles，按固定步长蓄力、发射、贴地位移与伤害。Renderer 只绘制蓄力和弹道，窄屏对尚在屏外的威胁给出提示。暂停/对白不调用 update，恢复检查点清空弹道并跳过已过敌人；无需持久化飞行中的弹道。HUD 的 playing 样式缩减上下边栏，模式切换和 ResizeObserver 同步画布尺寸。

`node tools/verify-chapter.mjs` 从正式单文件生成 `.verify/chapter-flow.html`，测试内存存储隔离于玩家存档，并记录写入次数；驱动真实按钮与键盘输入，消费正式事件。覆盖全路线、16 处对白、三幕分镜、主按钮衔接、暂停/重玩/重开与结算。新增纯享全 98 页、目录跳转与键盘选择、模拟/存档快照不变，以及 Boss 合集、两场无伤练习、巨像重战和暂停重开。历史初版 55 项，当前 417 项断言。结果在 `.verify/chapter-flow-report.json`。回放验证存在可通过路线，不代表真实玩家盲玩已完成。

## 纯享与练习的状态隔离

`story-theater.js` 只组合 `CHAPTER_STORIES`、`INTERMISSION_PANELS`、两幕 `ENCOUNTERS` 与必要 `ALL_ENTRIES`。`storyPhase=theater` 复用 intro 屏幕，操作只改 `theaterReel/storyPanels/storyIndex`；完成移到下一段，跳过退出菜单。不会调用游戏重置/关卡载入、`Narrative.unlock` 或 `ProgressStore`。正式幕间跳过仍归档，纯享回看不归档。目录 select 保留原生方向键，空格聚焦目录按钮时也不误翻正文。阅读音乐使用既有 journal 混音。

`BOSS_CHANNELS` 提供两个练习入口。`placeInBossArena` 重置 Runner，将 x 与检查点放在对应 trigger 前一帧，第二幕共享正式 `COVENANT.boss`；触发、伤害、断链、震波都由同一 Runner 执行。练习清空路线机关与收集，重试回触发点前并清轮数。`start/replay/restart` 根据当前 bossOnly 关卡返回原练习，不硬编码桥战；练习 won 不清正式存档、不归档，并隐藏主线锁进度。

`encounterKind` 供正式对白和纯享共用，防止肖像与说话者错配。烬肖像依据 visual-kit 概念图重绘为原生 SVG，Canvas 跑步姿态、碰撞和物理未换成 3D。visual-kit 整包未加入打包；远景设计要素由独立的 background-depth 原生模块适配，剩余特效与设备性能检查仍属 T-06/T-02，参见[素材评审](visual-kit-review.md)。

## 创作者输入与共享文本

`beginStoryTheater` 只接受显式 `true` 进入创作者模式，普通按钮的 MouseEvent 不能冒充授权。密码门仍按用户要求作简单字符串比较；没有服务器身份验证。story-editor 注册分镜、幕间五页、必要手记、对白及战斗摘要，纯享 98 页都持有 editKey。保存/恢复修改共用源、刷新当前纯享副本并使手记缓存失效；覆盖使用独立 localStorage 键，不改变 ProgressStore。

窗口 keydown/keyup 在创作者 intro 中立即返回，不 preventDefault，不阻断输入法与原生文字编辑；游戏暂停、音乐、手记、翻页等快捷键均停用。输入框在其他模式也不响应游戏按键。创作者通过按钮/原生下拉目录导航，退出编辑恢复只读纯享快捷键；body.dataset.creator 控制提示与小窗口滚动布局。打包页面检查实际密码门、三字段/窗口按键、保存/恢复、幕间同步、98 页来源、退出后键位恢复和翻页可见性，测试覆盖存储隔离于玩家数据。

## 三幕远景层次

BackgroundDepth 在各场景原山体之后、原生地标之前绘制，不持有 Runner。距离驱动 .026/.055 两层视差，四类几何循环缓存；每类每层只生成一次，窗灯绑定房屋，不随动画时间漂移。所有新增内容裁剪在 y≤450，底部渐隐；风海减少建筑，遗迹不加人物或窗灯。保持原序章、路面、照忆桥墙、法术及碰撞。

`node tools/verify-backgrounds.mjs` 读取正式离线包，关闭同一份随机脚下扬尘，以同一时间/模拟快照比较原版和新增远景；输出十二处场景的原像素对照及 .verify/background-depth-report.json。`--small` 使用 960×600，桌面和小窗口各 37 项通过，y≥460 路面/实体像素一致、背景可见、地图/模拟不变、滚动缓存有界。此检查与 Canvas 几何缓存不证明真实设备帧率已经提高。

## 第三幕照忆与救援

level-fate.js 声明 echoPlatforms / echoWalls / rescues / greyChase。Runner 的 setEcho 接受实际长按输入；platformAt 与 supportAt 共同查询照亮的旧桥，封墙 AABB 只在光亮时存在。绘制层读同一状态，不以淡出透明度决定碰撞。校验要求落脚距离、墙两侧空中间隙、救援手动旗标与可追逐速度合法。

救援点将玩家停在灯前，持光且落地才累计 1.1 秒；读对白/略过不发放救援。首次救援发出 fate-sacrifice 手动旗标，灰潮从固定起点以 320/s 追来；后两点分别注火，rescue 事件只触发表现。rescues 的完成状态记在关卡 manual flags，通用经过旗标不会提前触发它们。rescueTimes 只为救出人物短暂离场表现；保存点都在救援前，失败清临时进度与追逐时钟，恢复已存余火/证据，不能用已读手记冒充已救人。

E 与触屏长按同接口，松开/取消解除输入；暂停、对白、手记与过场不调用 update，不改变照忆支撑、注火或灰潮时钟。输入释放在阅读中只改待恢复的 held 值，恢复后按实际按键状态应用，避免触屏取消后卡住。纯享以 picture.level / phase / index 引用相同 SVG，第三幕肖像缩至边角保留证据现场。命运地标独立分支，绝不落入记名桥三助手绘制。

新增 tests/fate.test.mjs 覆盖整幕/各检查点、恒亮/恒暗不可代替切换、真实注火/回档/存档、证据顺序、纯享复用、文本恢复、地标人物隔离。浏览器通过实际 KeyE 事件回放，并在照忆落脚与注火时验证暂停快照。
